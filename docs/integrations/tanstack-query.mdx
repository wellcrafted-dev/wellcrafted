# TanStack Query Integration

`wellcrafted/query` adapts Result-returning services for TanStack Query, and adapts TanStack back to Results for workflows. It exports four functions:

| Function | Direction | What it does |
| --- | --- | --- |
| `resultQueryOptions(input)` | Result to TanStack | Turns a Result-returning `queryFn` into plain query options. `Ok` resolves, `Err` throws into the error channel. |
| `resultMutationOptions(input)` | Result to TanStack | The same for a `mutationFn`. Callbacks receive TanStack's mutation context, including `client`. |
| `runQuery(client, options)` | TanStack to Result | Reads through the cache with `client.query` and returns a Result. |
| `runMutation(client, options, variables)` | TanStack to Result | Runs a mutation through the mutation cache and returns a Result. |

Install TanStack Query 5.102 or later. `@tanstack/query-core` is an optional peer dependency, and every framework adapter already depends on it.

## Quick start

Create the client once:

```typescript
// lib/query/client.ts
import { QueryClient } from '@tanstack/query-core';

export const queryClient = new QueryClient();
```

Define keys, queries, and mutations. None of them take a client:

```typescript
// lib/query/todos.ts
import { resultMutationOptions, resultQueryOptions } from 'wellcrafted/query';
import * as api from '../services/todos'; // each function returns Result<T, TodoError>

const todosRoot = ['todos'] as const;

export const todoKeys = {
  all: todosRoot,
  lists: [...todosRoot, 'list'] as const,
};

export const todoQueries = {
  list: (filter: TodoFilter) =>
    resultQueryOptions({
      queryKey: [...todoKeys.lists, filter],
      queryFn: () => api.listTodos(filter),
    }),
  detail: (id: string) =>
    resultQueryOptions({
      queryKey: [...todosRoot, 'detail', id],
      queryFn: () => api.getTodo(id),
    }),
};

export const addTodo = resultMutationOptions({
  mutationKey: [...todosRoot, 'add'],
  mutationFn: (title: string) => api.addTodo(title),
  onSuccess: (_todo, _title, _onMutateResult, { client }) =>
    client.invalidateQueries({ queryKey: todoKeys.lists }),
});
```

## Using definitions in components

The definitions are plain TanStack options, so hooks take them directly. The error type comes from the service's Result.

<Tabs>
  <Tab title="React">

```tsx
import { useMutation, useQuery } from '@tanstack/react-query';
import { addTodo, todoQueries } from '../lib/query/todos';

function TodoList({ filter }: { filter: TodoFilter }) {
  const todos = useQuery(todoQueries.list(filter));
  const add = useMutation(addTodo);

  if (todos.isPending) return <Spinner />;
  if (todos.error) return <ErrorMessage error={todos.error} />; // TodoError

  return (
    <>
      {todos.data.map((todo) => <TodoRow key={todo.id} todo={todo} />)}
      <button disabled={add.isPending} onClick={() => add.mutate('New todo')}>
        Add
      </button>
    </>
  );
}
```

  </Tab>
  <Tab title="Svelte 5">

```svelte
<script lang="ts">
  import { createMutation, createQuery } from '@tanstack/svelte-query';
  import { addTodo, todoQueries } from '$lib/query/todos';

  let { filter }: { filter: TodoFilter } = $props();

  // The thunk re-runs when `filter` changes.
  const todos = createQuery(() => todoQueries.list(filter));
  const add = createMutation(() => addTodo);
</script>

{#if todos.isPending}
  <Spinner />
{:else if todos.error}
  <ErrorMessage error={todos.error} />
{:else}
  {#each todos.data as todo (todo.id)}
    <TodoRow {todo} />
  {/each}
  <button disabled={add.isPending} onclick={() => add.mutate('New todo')}>Add</button>
{/if}
```

Everything else in TanStack that accepts options works the same way: `useQueries` and `queryClient.query`. Override any option by spreading: `useQuery({ ...todoQueries.detail(id), enabled: !!id })`.

### Awaiting a mutation

`mutate` returns nothing. Its errors reach `add.error` and `onError`, which are typed. `mutateAsync` returns a promise, and TypeScript cannot type a promise's rejection, so a `catch` around it gets `unknown`. Do not use `mutateAsync` with Result definitions.

When a handler has to wait for the mutation, for example to close a dialog only on success, skip the mutation hook and run the definition with `runMutation`. Take the pending flag from `useIsMutating`:

<Tabs>
  <Tab title="React">

```tsx
import { useIsMutating, useQueryClient } from '@tanstack/react-query';
import { runMutation } from 'wellcrafted/query';
import { addTodo } from '../lib/query/todos';

function AddTodoButton({ title, onClose }: { title: string; onClose: () => void }) {
  const queryClient = useQueryClient();
  const adding = useIsMutating({ mutationKey: addTodo.mutationKey }) > 0;

  async function submit() {
    const { error } = await runMutation(queryClient, addTodo, title);
    if (error) return toast.error(error.message); // TodoError
    onClose();
  }

  return <button disabled={adding} onClick={submit}>Add</button>;
}
```

  </Tab>
  <Tab title="Svelte 5">

```svelte
<script lang="ts">
  import { useIsMutating, useQueryClient } from '@tanstack/svelte-query';
  import { runMutation } from 'wellcrafted/query';
  import { addTodo } from '$lib/query/todos';

  let { title, onClose }: { title: string; onClose: () => void } = $props();

  const queryClient = useQueryClient();
  const adding = useIsMutating({ mutationKey: addTodo.mutationKey });

  async function submit() {
    const { error } = await runMutation(queryClient, addTodo, title);
    if (error) return toast.error(error.message); // TodoError
    onClose();
  }
</script>

<button disabled={adding.current > 0} onclick={submit}>Add</button>
```

  </Tab>
</Tabs>

This runs the same definition through the same mutation cache as the hook: `onSuccess` invalidates, devtools show the run, and `useIsMutating` counts it. Three things differ from `useMutation`:

- **Pending is shared.** `useIsMutating` counts every pending run of that key, so two forms adding todos at once both disable. If only this component's run should count, keep a local flag around the `await`.
- **The outcome lives in the Result.** No `add.data` or `add.error` persists after the handler returns; keep what you need in your own state.
- **Unmounting does not drop the outcome.** Callbacks passed to `mutate(vars, { onSuccess })` do not fire once the component unmounts. The awaited Result still arrives.

## Keys and option factories

The key factory holds groups: the root and the prefixes you invalidate together. A group belongs to no single query. Option factories own the leaf keys, and build each one by spreading a group.

Spreading the root guarantees every key starts with it, so `invalidateQueries({ queryKey: todoKeys.all })` reaches every leaf by construction. The root is its own constant because referencing `todoKeys.all` inside its own object literal can trip TypeScript's circularity check. Spread keys stay literal tuples, so `as const` is optional on leaf keys.

| You want to | Use |
| --- | --- |
| Invalidate, cancel, or refetch a group | `todoKeys.all`, `todoKeys.lists` |
| Do anything with one entry: read or write its data, invalidate exactly it | `todoQueries.detail(id).queryKey` |

The leaf key carries a `DataTag`, as with TanStack's own `queryOptions()`, so cache access is typed without a cast:

```typescript
const { queryKey } = todoQueries.detail(id);
queryClient.getQueryData(queryKey); // Todo | undefined
queryClient.setQueryData(queryKey, (old) => old && { ...old, done: true });
```

<Tip>
Extract a leaf key into the key factory only when some code needs it without the option factory, such as a module that cannot reach the API client or session. Keep the smaller piece underneath, and pull it out only when it must be reused on its own.
</Tip>

## Mutations and invalidation

`mutationFn(variables, context)` and every lifecycle callback receive TanStack's `MutationFunctionContext`: `{ client, meta, mutationKey }`. Invalidate and update the cache through `context.client` instead of importing a client into the definition:

```typescript
export const toggleTodo = resultMutationOptions({
  mutationKey: [...todosRoot, 'toggle'],
  mutationFn: (id: string) => api.toggleTodo(id),
  onSuccess: (todo, id, _onMutateResult, { client }) => {
    client.setQueryData(todoQueries.detail(id).queryKey, todo);
    return client.invalidateQueries({ queryKey: todoKeys.lists });
  },
});
```

Optimistic updates follow the standard TanStack shape, with the client from the context:

```typescript
export const renameTodo = resultMutationOptions({
  mutationKey: [...todosRoot, 'rename'],
  mutationFn: (input: { id: string; title: string }) => api.renameTodo(input),
  onMutate: async ({ id, title }, { client }) => {
    const { queryKey } = todoQueries.detail(id);
    await client.cancelQueries({ queryKey });
    const previous = client.getQueryData(queryKey);
    client.setQueryData(queryKey, (old) => old && { ...old, title });
    return { previous };
  },
  onError: (_error, { id }, onMutateResult, { client }) => {
    client.setQueryData(todoQueries.detail(id).queryKey, onMutateResult?.previous);
  },
  onSettled: (_data, _error, { id }, _onMutateResult, { client }) =>
    client.invalidateQueries({ queryKey: todoQueries.detail(id).queryKey }),
});
```

## Imperative use

Event handlers and workflows run the same definitions and get Results back:

```typescript
import { CancelledError } from '@tanstack/query-core';
import { runMutation, runQuery } from 'wellcrafted/query';
import { queryClient } from './client';

async function duplicateTodo(id: string) {
  const { data: todo, error } = await runQuery(queryClient, todoQueries.detail(id));
  if (error instanceof CancelledError) return;
  if (error) return showError(error);

  const { error: addError } = await runMutation(queryClient, addTodo, todo.title);
  if (addError) return showError(addError);
}
```

`runQuery` wraps `client.query`, which replaces TanStack's deprecated imperative reads. Fresh cached data returns without a request, stale or missing data is fetched, and concurrent calls for one key share a request. To accept any cached data and fetch only on a miss, pass `{ ...todoQueries.detail(id), staleTime: 'static' }`. Its error side includes `CancelledError`; check it with `instanceof`, since `isCancelledError` is deprecated upstream.

`runMutation` runs through a public `MutationObserver`, so the definition's callbacks run, invalidation happens, and `useIsMutating`, `useMutationState`, mutation scopes, and devtools all see it.

<Note>
The imperative helpers exist to go through the cache: deduplication, cache fill, staleness, mutation callbacks, and `isMutating`. If nothing observes the data, call the service directly.
</Note>

## Result in, Result out

Services return Results. The `result*Options` adapters turn them into TanStack's throwing contract, and `runQuery`/`runMutation` turn TanStack back into Results. Pass the Result-returning function straight to the adapter; do not unwrap and throw by hand.

To change the error a component sees, map it inside `queryFn` and keep returning a Result:

```typescript
queryFn: async () => {
  const { data, error } = await api.getTodo(id);
  if (error) return Err({ title: 'Could not load todo', description: error.message });
  return Ok(data);
},
```

## Client lifetime

Definitions take no client, so you choose the client's lifetime where you call.

<Tabs>
  <Tab title="Single-page app">

One client in one module. Hooks get it from the provider; workflows import it.

```typescript
export const queryClient = new QueryClient();
```

  </Tab>
  <Tab title="SSR or per session">

Create a client per request or session and use the same definitions. No definition holds a client, so nothing leaks between requests.

When a definition needs per-session transport, build the option factories inside the session constructor. They close over the transport and still take no client; the key factory stays at module level.

```typescript
export function createTodoQueries(api: TodoApi) {
  return {
    detail: (id: string) =>
      resultQueryOptions({
        queryKey: [...todosRoot, 'detail', id],
        queryFn: () => api.getTodo(id),
      }),
  };
}
```

  </Tab>
</Tabs>

## Migrating from 0.44

| Before | After |
| --- | --- |
| `createQueryFactories(queryClient)` | Delete. Import `resultQueryOptions` and `resultMutationOptions`. |
| `defineQuery(...)` / `defineMutation(...)` | `resultQueryOptions(...)` / `resultMutationOptions(...)` |
| `useQuery(userQuery.options)` | `useQuery(userQuery)` |
| `createQuery(() => userQuery.options)` | `createQuery(() => userQuery)` |
| `await userQuery.fetch()` | `await runQuery(queryClient, userQuery)` |
| `await userQuery.ensure()` | `await runQuery(queryClient, { ...userQuery, staleTime: 'static' })` |
| `await createPost(input)` | `await runMutation(queryClient, createPost, input)` |
| Captured `queryClient` in a mutation | `context.client` in `mutationFn` or a callback |
| `defineKeys(...)` | A plain `as const` key factory for groups; leaf keys inside option factories |
